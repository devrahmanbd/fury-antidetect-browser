# 12 — UX-референс: разбор AdsPower

За образец интерфейса берём AdsPower. Он не самый сильный по отпечатку, но
**командная работа и повседневная эргономика у него лучшие на рынке** — и именно
это надо повторить, а потом улучшить в трёх местах, где у него нет решения.

Ниже разбор реального экрана «Профили» и выводы для Fury.

## Что устроено правильно и надо повторить

### 1. Список профилей — это и есть приложение

Нет дашборда, нет «домашней страницы», нет экрана приветствия. Открыл программу —
сразу таблица профилей. Всё остальное (группы, прокси, расширения, автоматизация) —
второстепенные разделы в сайдбаре.

Это правильно: пользователь заходит десять раз в день, чтобы открыть профиль.
Любой экран между запуском и списком — трение.

**Для Fury:** окно открывается на списке профилей последнего проекта. Никакого
онбординга после первого раза.

### 2. Основное действие продублировано в двух местах

Кнопка «Открыть» есть и в тулбаре (для выделенных), и в каждой строке справа.
Плюс контекстное меню «⋮» на строке для всего остального.

Не «избыточность», а разные сценарии: открыть один профиль → кнопка в строке;
открыть пачку → выделить чекбоксами и тулбар.

### 3. Тулбар массовых операций всегда на месте

Постоянная панель над таблицей: Открыть, RPA, синхронизатор, закрыть все,
экспорт, импорт, поделиться, удалить, «...». Не появляется/исчезает при
выделении — просто становится активной. Кнопки не прыгают, мышечная память
работает.

### 4. Колонка прокси показывает то, что нужно перед запуском

В одной ячейке: иконка типа прокси, флаг страны, IP, название страны. Оператору
надо **до** открытия профиля понять, тот ли выход. Не «прокси №4», а
реальный IP и гео.

### 5. Иконка ОС рядом с именем профиля

Значок платформы прямо в колонке имени — видно, какая ОС в отпечатке, не открывая
профиль. Мелочь, которая экономит клики каждый день.

### 6. «Последнее открытие» — полноценная колонка с сортировкой

Ключевая метрика для того, кто ведёт аккаунты: какие профили залежались.
Аккаунт, который не открывали два месяца, ведёт себя иначе, чем живой.
Сортировка по этой колонке — рабочий инструмент, а не украшение.

### 7. Квоты всегда видны в сайдбаре

Внизу постоянно: сколько профилей из лимита, сколько пользователей из лимита,
до какой даты активна подписка. Пользователь никогда не упирается в лимит
внезапно.

**Для Fury** биллинга нет, но принцип остаётся: показывать в сайдбаре
**число профилей, число участников и состояние связи с сервером**. Последнее
важнее всего — оператор должен видеть, работает ли он онлайн или на локальном
кэше ([06](06-profile-sync.md)).

### 8. Фильтр групп + поиск с сохраняемыми критериями

Слева дропдаун группы, справа поиск с иконкой расширенных фильтров
(«Поиск или новые критерии поиска»). При сотнях профилей это единственный
способ работать.

### 9. Корзина, а не удаление

Отдельный раздел «Корзина». Профиль с прогретым аккаунтом нельзя терять по
случайному клику.

### 10. Настраиваемые колонки

Иконка справа в шапке таблицы. У разных ролей разные потребности: менеджеру
нужны теги и группы, оператору — прокси и время последнего открытия.

## Структура навигации (берём почти как есть)

```
[Новый профиль]          ← primary-кнопка, самая заметная в окне

Профили                  ← активный по умолчанию
Группы
Прокси
Расширения
Корзина

АВТОМАТИЗАЦИЯ
  Синхронизатор          ← одновременное управление N окнами
  RPA                    ← no-code сценарии
  API                    ← локальный API (docs/05)

КОМАНДА
  Участники
  Права доступа
  Аудит-лог              ← у AdsPower слабее всего, см. ниже

──────────────────────
[состояние: онлайн/офлайн]
профили N · участники M
```

Одно отличие: у AdsPower иерархия — **группы**, плоские метки. У нас
**проекты** ([04](04-data-model-rbac.md)), потому что проект — единица выдачи
доступа. Группы внутри проекта оставляем как второй уровень для удобства.

**Из этой схемы не построен «Синхронизатор», и это стоит заметить отдельно.**
Пересмотр рынка 14.08.2026 внёс его как задачу 5.1
([16](16-parity-and-beyond.md)) со ссылкой на AdsPower и Dolphin — но он стоял
здесь, в нашей собственной раскладке навигации, до всякого разбора конкурентов.
То есть это не заимствование, а невыполненный пункт своего же плана, и довод в
его пользу свой: лончер уже держит N браузеров и выдаёт CDP к каждому.

Разделы «Расширения» и «Корзина» из схемы построены (`agent/src/ext.rs`,
`Trash.tsx`), «RPA» сознательно не построен — см. ниже.

## Три места, где надо сделать лучше

Это и есть продуктовая дифференциация. Всё остальное — паритет.

**Состояние на 14.08.2026, сверено с кодом:** A сделан, B сделан наполовину,
C не сделан. Раздел писался как план и с тех пор ни разу не сверялся с
`ProfileTable.tsx`, поэтому ниже у каждого пункта приписано, что там на самом
деле.

### A. Колонка блокировки — кто держит профиль прямо сейчас

У AdsPower профиль просто «открыт». У нас есть распределённый лок
([06](06-profile-sync.md)), и его состояние обязано быть в таблице:

```
🟢 свободен
🔵 открыт: Аня · MacBook-Anya · 14 мин
🟠 не синхронизирован — закрыт некорректно, есть локальные изменения
🔴 занят другим · [Снять принудительно]  ← только при manage_access
```

Без этого командная работа превращается в переписку «ты закрыл третий?».
Это самая частая операционная боль в агентствах, и её никто не закрыл.

**Сделано** ([ProfileTable.tsx](../desktop/src/components/ProfileTable.tsx)), и с
уточнением, которого в плане не было: «мой» лок определяется по паре
пользователь + машина, а не по пользователю. Один и тот же человек, вошедший с
ноутбука и с десктопа, иначе видел бы живой лок ноутбука как «открыт здесь» — с
рабочей кнопкой «Закрыть», снимающей лок с браузера, который в это время
запущен на другой машине.

### B. Бейдж консистентности отпечатка

Валидатор уже написан ([shared-rs/src/fingerprint.rs](../shared-rs/src/fingerprint.rs)).
Его результат — прямо в строке:

```
✓ консистентен
⚠ таймзона профиля не совпадает с гео IP     ← запуск блокируется
⚠ WebGL заявляет NVIDIA на macOS-персоне
```

Ни один продукт на рынке не показывает этого в списке. При этом именно
несостыковка, а не «плохой отпечаток», — причина большинства банов.

Правило из [01](01-architecture.md): красный бейдж = кнопка «Открыть»
неактивна с объяснением. Не предупреждение, которое проматывают.

**Сделано наполовину, и недостающая половина — как раз та, ради которой пункт
писался.** Вердикт валидатора показывается в редакторе профиля (`pd.consistent`
в [i18n.ts](../desktop/src/i18n.ts)), то есть там, где человек и так занят этим
профилем. **В строке таблицы его нет.** Дифференциация была именно в списке:
оператор со ста профилями не открывает редактор каждого, чтобы узнать, какие из
них противоречивы. Задача 5.9 в [16](16-parity-and-beyond.md).

### C. Счётчик профилей на одном IP

В колонке прокси: `RU · 46.x.x.x · ⚠ 4 профиля`. Несколько аккаунтов с одного
IP — классический признак фермы для антифрода. AdsPower это допускает молча.

**Не сделано.** Поиск по `desktop/src` и `agent/src` не находит ничего похожего.
Колонка прокси показывает адрес и страну (страну — только после проверки, и до
неё честно говорит об этом вместо голого «?»), но сколько профилей делят этот
выход, не считает никто. Задача 5.10 в [16](16-parity-and-beyond.md).

### D. Статус профиля — то, чего не хватает по сравнению с рынком

Добавлено пересмотром 14.08.2026 ([08](08-competitors.md)). Колонка «Статус» в
таблице занята состоянием **лока** — свободен, открыт, занят другим. Стадия
самого аккаунта — «в прогреве», «на бане», «готов» — не выражается ничем.

Теги это не закрывают: тег — принадлежность, статус — состояние, и по нему
нужны фильтр и цвет. Есть у Octo, Dolphin и GoLogin сразу, у каждого со своим
набором. Задача 5.5.

## Что не копируем

- **Cloud Phone и облачные профили.** Требует парка машин, несовместимо
  с бесплатной моделью ([08](08-competitors.md)).
- **RPA-конструктор в v1.** Local API закрывает потребность для тех, кто умеет
  писать код. Визуальный конструктор — большой отдельный продукт.
  Уточнение от 14.08.2026: отказ относится к **конструктору сценариев и
  маркетплейсу шаблонов** (AdsPower RPA, Dolphin Scenario Builder), но не к
  синхронизатору окон. Их легко слить в один отказ, и это была бы ошибка: 5.1
  даёт основную часть пользы и стоит на порядок дешевле.
- **Реферальные баннеры и апселлы в сайдбаре.** Продавать нечего.

## Права доступа отражаются в UI

UI скрывает недоступное, но это **презентация, а не защита** — enforcement
в [rbac_guard.rs](../server/src/rbac_guard.rs) и в самом ядре, в патчах, которые
читают флаги запуска: [0302](../core/patches/0302-devtools-lock.patch) для
`lock_devtools`, [0303](../core/patches/0303-data-export-lock.patch) для
`lock_data_export`.

Здесь раньше было написано «enforcement … в флагах запуска (launcher.rs)», и это
была ровно та ошибка, которую эти два патча закрыли: launcher.rs толкал
`--fury-lock-devtools` и `--fury-lock-data-export` при каждом ограниченном
запуске, а grep по `core/src` не находил ни одного вхождения. Обе «технические»
блокировки были скрытыми кнопками — оператор, которому запрещено уносить данные
профиля, открывал DevTools и читал оттуда cookies. Флаг — это просьба; запретом
он становится там, где его читают.

| Право отсутствует | Что видит пользователь |
|---|---|
| `reveal_secrets` | Прокси как `res-***.provider.net · GB`, пароли как `••••` без кнопки показать |
| `export_cookies` | Нет кнопок экспорта и «поделиться», в меню строки они отсутствуют |
| `edit_fingerprint` | Редактор отпечатка открывается только для чтения |
| `delete_profile` | Кнопка удаления отсутствует, не «выдаёт ошибку при клике» |
| `manage_access` | Нет раздела «Права доступа», нет «Снять блокировку принудительно» |

Отдельно про CDP, и это не про прятание в UI. У оператора без `export_cookies`
CDP не выдаётся вовсе: сервер считает `deny_cdp = !export_cookies`
([rbac.rs:171-181](../shared-rs/src/rbac.rs)), и лаунчер тогда просто не кладёт
`--remote-debugging-port` в argv ([launcher.rs:196-202](../agent/src/launcher.rs)).
Прятать «токен локального API для этого проекта», как было записано здесь
раньше, защитой быть не могло: токен один на машину и лежит в файле `api-token`
рядом с базой агента, режим 0600 ([http.rs:47-74](../agent/src/http.rs)).

## Технические решения по UI

- **Tauri 2 + React + TypeScript.** Инсталлятор ~10 МБ против ~120 у Electron,
  а рядом уже лежит 200-МБ Chromium.
- **Таблица пока не виртуализована.** `@tanstack/react-virtual` в
  [desktop/package.json](../desktop/package.json) нет, а
  [ProfileTable.tsx](../desktop/src/components/ProfileTable.tsx) рендерит
  `profiles.map(...)` целиком — все строки сразу. Решение остаётся прежним:
  пагинация в 2026 — компромисс от бессилия, виртуальный скролл на 5000 строк
  работает без неё. Но на сегодня это план, а не свойство сборки, и на
  нескольких тысячах профилей это станет заметно раньше всего остального.
- **Тема по умолчанию системная, не тёмная.** `useTheme()` стартует с `"system"` и разрешает её через `prefers-color-scheme` ([theme.ts:6,20,29](../desktop/src/theme.ts)), так что на светлой macOS приложение светлое. Хранится буквальный выбор из трёх — `system`, `dark`, `light`, — чтобы «системная» шла за десктопом на закате. Довод в пользу тёмной по умолчанию (в инструменте сидят по 10 часов) не отменён, он просто не реализован.
- **Состояние берётся поллингом, не подпиской.** `setInterval` на 5 секунд
  перечитывает профили, проекты и состояние агента
  ([App.tsx:149-156](../desktop/src/App.tsx)) — включая shell_state, потому что
  агент, умерший при открытом приложении, иначе оставлял предупреждение на
  экране навсегда. IPC-подписка остаётся тем, чего хочется: статус лока и
  запущенности меняется часто, и пятисекундная задержка в командном режиме
  видна. Сегодня таблица обновляется опросом.

## Аудит по экранам AdsPower 8.4.3 — 12.09.2026

Шесть скриншотов живого AdsPower, сверенные с нашим кодом. Правило то же, что
в [08](08-competitors.md): «есть» значит найдено в файле, а не в намерении.
Главная находка — не в списке чужих функций, а в нашем: **расширения написаны
целиком и не видны ни из одного экрана.**

### 1. Расширения: у нас есть агент, нет интерфейса

AdsPower: раздел «Расширения» в сайдбаре, две вкладки — «Расширения команды»
(загруженные, назначаются профилям) и «Рекомендуемые» (каталог по категориям
со ссылками в Chrome Web Store), поиск.

У нас: `agent/src/ext.rs` разбирает CRX3, вписывает ключ разработчика в
манифест, чтобы ID пережил клонирование, — работа, которой нет у большинства
платных. IPC `extensions.install / list / remove` есть (`ipc.rs:509`).
**В `desktop/src` слово «extension» встречается один раз — в подсказке к
импорту cookies.** Ни кнопки, ни списка, ни раздела. [16](16-parity-and-beyond.md)
отмечает 1.1 «сделано» — это верно про агент и неверно про продукт: для
пользователя расширений нет.

Что делать — в порядке цены:

1. **Раздел «Расширения» в сайдбаре**: список установленных по профилю,
   «добавить .crx», удалить. Всё это — три вызова, которые уже есть.
2. **Установка по ID из Chrome Web Store**: CRX скачивается по известному URL
   `clients2.google.com/service/update2/crx?...&x=id%3D<id>%26uc`. Это
   загрузка с адреса, не являющегося прокси профиля — ровно возражение из
   `install_core.rs` против автозагрузки. Разница в том, что здесь не ядро, а
   подписанный Google архив, и скачивать его можно **через релей профиля**, для
   которого он ставится. Решение записать отдельно, не сделать молча.
3. **Общие расширения организации** («Расширения команды») — бандл
   расширения на сервере, назначение профилям проекта. Командная функция,
   наша ниша. После 1 и 2.
4. **Установка по id из Web Store — решение принято 12.09.2026: вариант B.**
   Скачивать `.crx` только через прокси того профиля, в который ставим
   (Google видит IP выхода профиля — ровно то, что видел бы при установке из
   самого браузера), и проверять, что ключ в CRX даёт запрошенный id
   (`ext.rs` это умеет). Прямая загрузка с машины оператора отвергнута:
   утечка IP оператора вместе с id расширения, которое говорит о намерении.
   Это 5.31 — **сделано 12.09.2026**: `agent/src/webstore.rs`, каталог в
   `shared/extensions/`, раздел «Каталог» в Расширениях.

5. **Каталог «рекомендуемых»** — витрину партнёров AdsPower (OctopusRPA,
   SocialEcho) не повторяем. Но предложение от 12.09.2026 — **раздел
   «Расширения» в сайдбаре с небольшим своим каталогом, который потом
   пополняет сообщество** — стоит отдельно от витрины и записано как 5.31.
   Что в каталоге должно быть с самого начала, и почему именно это: то, что
   оператор аккаунтов ставит в каждый профиль руками — редактор cookies
   (импорт/экспорт в наш формат), TOTP-аутентификатор (у нас уже есть
   хранилище с TOTP — расширение может брать код оттуда, не заводя второй
   секрет), блокировщик рекламы (иначе профиль без него аномален: у большей
   части настоящих пользователей он есть). Не в каталоге: кошельки и
   антикапчи — их ставят по ссылке разработчика, а каталог с «рекомендованной»
   антикапчей — это ответственность за чужой сервис. Формат каталога: файл в
   репозитории с id расширения, названием, хешем CRX и кем добавлено; PR от
   сообщества — тот же путь, что для персон (3.4). Установка по id из Chrome
   Web Store при этом — решение п. 2, без него каталог остаётся списком
   ссылок.

| Изменить прокси | через «Изменить» | достаточно |
| Редактировать аккаунт | `Logins.tsx` есть | достаточно |
| Изменить отпечаток | через «Изменить» → машина | достаточно |

Второй раз подряд одно и то же: `usage.rs` написан 07.08, вызывается из
`ipc.rs:397`, и ни одна кнопка его не дёргает. Это тот же дефект, что с
расширениями, и лечится тем же — экраном.

### 3. Настройки профиля («Обзор» отпечатка)

AdsPower показывает по профилю 25 строк с переключателями. Сверено построчно.
Три столбца: что у них, что у нас, решение.

| AdsPower | у нас | решение |
|---|---|---|
| Браузер: выбор версии ядра (SunBrowser Chrome 150 при stable 153) | версия следует за ядром, `CHROME_MAJOR` в агенте | **не делаем**: выбор старой версии — сам по себе отпечаток ([03](03-chromium-fork.md), N-1) |
| User-Agent (строкой) | из шаблона персоны | не редактируем: UA, не согласованный с Client Hints, ловится первым |
| WebRTC: отключить / заменить / реальный | патч 0070, маршрутизация через релей, без переключателя | не делаем переключатель: «реальный» — это утечка IP по кнопке |
| Часовой пояс: на основе IP | пустое поле = следовать за выходом, резолвится при каждом запуске (`ipc.rs:1535`) | есть, честнее: не «по IP из базы», а по выходу в момент запуска |
| Геолокация: [запрашивать] на основе IP | координаты из того же резолва выхода; permissions отвечают «prompt» до решения пользователя (0090) | есть |
| Язык: на основе IP | пустое поле = языки Chrome той страны, из локалей самого Chromium (`fury_shared::locale`) | есть, строже |
| Язык интерфейса браузера | `ui_locale` из языков | есть |
| Разрешение: на основе UA | из персоны | есть, строже |
| Шрифты: по умолчанию | из персоны, фильтр на уровне fallback | есть, строже |
| Canvas / WebGL image / AudioContext / ClientRects: шум / **реальный** / блок | звук и геометрия — всегда шум; canvas и WebGL-readback — **шум по умолчанию или «Реальный»** (`overrides.canvas`, вкладка «Дополнительно», с 28.09.2026); блока нет | Раньше «Реальный» сознательно не добавляли: у AdsPower это дефолт, и canvas байт в байт как у голой машины, то есть профили на одной машине связываются ([08](08-competitors.md)). Пересмотрено после замера 27.09.2026: pixelscan называет наш шум «Masking detected», а реальный Chrome — нет, и тестер с опытом Sphere/Vision просил не трогать canvas. Итог — выбор с ценой, написанной в подсказке: шум остаётся по умолчанию, чтобы прогретые профили не меняли отпечаток; «Реальный» — для одного аккаунта на машину или персоны из слепка этой же машины |
| SpeechVoices: шум | список голосов из персоны (0041) | есть, честнее шума |
| Медиа-устройства: шум | из персоны (0060) | есть |
| WebGL метаданные | из персоны | есть |
| WebGPU: на основе WebGL | из персоны, с проверкой вендора | есть, строже |
| CPU / RAM | из персоны, с валидатором | есть, строже |
| **Имя устройства, MAC-адрес** | нет | **не делаем**: страница не может прочитать ни то ни другое. Это строки для ощущения безопасности, не для сайта |
| Do Not Track | нет | не делаем: дефолт Chrome — выключено, и это правильный дефолт для «как у всех» |
| **Защита от сканирования портов** | **есть с 12.09.2026, и измерение показало, что до этого не было**: с локальным апстримом страница доставала до агента. Релей теперь отказывает всем локальным адресам до набора апстрима ([16](16-parity-and-beyond.md), 5.27) | переключатель не нужен — это не опция |
| Аппаратное ускорение: вкл/выкл | нет | не делаем: выключенное даёт SwiftShader в renderer — это маркер |
| Отключить функции TLS | нет | **не делаем, измерено**: ClientHello нашей сборки уже неотличим от Chrome, любая правка делает хуже ([16](16-parity-and-beyond.md), 2.3) |
| «Новый отпечаток» (перебросить) | смена машины в редакторе; отдельной кнопки «новый seed» **нет** | добавить кнопку в редактор, с предупреждением: у прогретого аккаунта смена отпечатка — потеря аккаунта |

Итог: из 25 строк 17 у нас есть в более строгой форме (значение из персоны или
из выхода прокси, а не переключатель), 6 не делаем с записанной причиной, две
— кнопки в редакторе.

**Почему у нас меньше переключателей, и это надо сказать в интерфейсе.**
AdsPower даёт 25 ручек, потому что продаёт ощущение контроля. Мы даём одну —
машину, — потому что переключатели по вектору и дали AdsPower профиль с
«защищённым» canvas, который на замере оказался незащищённым. Но пользователь,
пришедший из AdsPower, увидит «мало настроек» и решит, что мало и подмены.
Панель «Чем представится» (`pd.overview`) это и должна закрывать — и она
закрывает наполовину: показывает 10 строк, а AdsPower — 25. Дописать в неё
всё, что ядро реально отдаёт по этой персоне (WebGL renderer, WebGPU, голоса,
медиа-устройства, шрифты числом, DPR, Client Hints полностью), — это 5.16 в
статической форме, без запуска браузера. Динамическая форма — probe из
приложения — там же.

### 4. Поповер «Текущая сеть»

AdsPower: иконка в шапке → IP, область (страна / регион / город), кнопка
«Сетевая диагностика».

У нас: `proxies.check` возвращает `ip / country / timezone / loc` и пишет в
`last_*` прокси (`ipc.rs:682`); показывается в форме прокси и в колонке
таблицы. **Поповера по открытому профилю нет.** Механика есть, экран — нет.
Добавить: по запущенному профилю — выход релея (IP, страна, город, ASN), и
5.20 «диагностика простым языком» внутрь.

### 5. Журнал действий

AdsPower: вкладки «Вход», «IP», «Открытие», «Профили», «Группы», «Прокси»,
«Процессы», «Участники», «Теги», фильтр по датам и оператору.

У нас: `GET /v1/audit`, `Audit.tsx` — один список, владельцам и админам.
`audit_events` пишется с миграции 0001. Что нужно — **не** девять вкладок, а
три вещи: фильтр по типу события (открытие профиля, вход, изменение прав,
прокси), по участнику, по датам; и **журнал входов с IP и устройством** —
его у нас нет как события вообще (`server/src` не пишет login-события с IP).
Это часть 5.3.

### 6. Глобальные настройки

| Раздел AdsPower | у нас | решение |
|---|---|---|
| **Безопасность аккаунта**: напоминание о входе с нового IP, оповещение о неудачных попытках, allowlist IP при входе, 2FA с уровнями (при каждом входе / с нового устройства / раз в 30-90 дней) и на отдельные действия (удаление профиля, управление участниками) | opaque-токены + Argon2id, и всё | **5.3**, и уровни 2FA — хорошая модель: TOTP у нас уже написан (`shared-rs/src/totp.rs`), его можно применить к входу, а не только к хранилищу логинов. | **Multi Device**: несколько человек открывают один профиль одновременно, глобально или по списку | лок на профиль, «перехватить» | не делаем глобально: одновременное открытие = две сессии с одним cookie-jar, что и убивает аккаунт. Лок — правильнее. Оставить как есть, записать причину |

| Статические ресурсы FB по локальной сети | нет | не делаем: трафик мимо прокси по кнопке |
